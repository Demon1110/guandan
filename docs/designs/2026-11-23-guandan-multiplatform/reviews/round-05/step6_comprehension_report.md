## 结论

- **可直接开工的部分**：§5.13 的四段判定（名次三种收尾、升级档、过 A 与 `aFailStreak` 的 `+1` 与清零、抗贡整段跳过且不还贡）读一遍即可写出按 phase 的动作级判定；§5.2 参数表覆盖了 §5.2 原语清单的全部原语，逐项都有类型、取值、默认值，可直接落成 `PrimitiveParams` 的具名变体。
- **阻断的部分**：`view` 的字段级 JSON 形态缺失（F6-01）是"两端契约"层面的缺口——客户端从 M1 接牌桌那一刻就无法解码快照、也无法复算 `viewHash`，因此本轮判 1 条 Blocker，而不是措辞问题。
- **M3 发布链开工前必须定死的**：F6-04（`ruleset` 行的 `version` 与 `pinned_interpreter_version` 归属）、F6-05（`full` 行的 active 唯一性与回滚候选）、F6-06（对账等式）、F6-07（`rating` 的计算端与取整）。
- **关于 manifest 的 `missing` 项 `crates/protocol/proto/gf/v1.proto`**：它是设计引用的待建路径，读不到属正常，本轮不据此判 incomplete、也不作为缺陷；只有当 §5.9 的消息字段本身缺定义时才计为缺陷（即 F6-01、F6-03）。
- **隔离与降权**：manifest 记录本轮隔离为 fresh-subagent-query-leak（`zero_context=false`，原始请求由框架透传），结论按该条降权使用；7 个来源 URL 未获人批准，本轮未抓取，因此不涉及 §4.2 外部事实的复核。
